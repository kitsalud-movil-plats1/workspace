# sw01, MikroTik CCR2004-16G-2S+PC

Ficha del equipo que hace de switch del kit. Es un router (Cloud Core Router) usado **solo en capa 2**. El diseño de referencia está en `docs/arquitectura/00-punto-de-partida.md`, D-03 y sección 5.2.

**Estado (2026-10-09).** Configuración base aplicada (`network/switch/sw01.rsc`). Hora por NTP desde `10.20.20.10` (Chrony en kit01) desde el 2026-10-10. Syslog hacia kit01 desde el 2026-10-27 (observability#3). Quedan pendientes DHCP snooping y filtro de RA.

| Grupo | Puertos | Nota |

## Cómo se convierte en switch

En RouterOS cada puerto es por defecto una interfaz de router. Para que conmute se aplica lo siguiente.

- Bridge `bridge-kit` con `vlan-filtering=yes` y filtrado de ingreso; los puertos en uso son miembros del bridge.
- `/interface bridge vlan`: qué VLAN lleva cada puerto y si va etiquetada.
- Una sola dirección, en la interfaz `vlan10-Interna` sobre el bridge, `10.20.10.2/24` y `fd5a:fc7e:d716:10::2/64`, ruta por defecto a `10.20.10.1`.
- Reenvío desactivado con `/ip settings set ip-forward=no` y `/ipv6 settings set forward=no`.
- Protección (network#11). DHCP snooping con ether1 como único puerto de confianza; lista de interfaces `acceso` (ether2, ether4-ether8) con `hw=no` y una regla de `/interface bridge filter` que descarta el IPv6 hacia `33:33:00:00:00:01` que entra por ella; `/ip service` limitado a kit01 y las IPs de administración, solo IPv4; telnet, FTP, web y API desactivados. El usuario `admin` es el usuario compartido del grupo (D-18) y conserva su contraseña por alcance académico.

**Cuidado al activar `vlan-filtering`.** Si se activa antes de definir la VLAN de gestión y su puerto, se pierde el acceso por la red. Configurarlo desde la consola serial o con Winbox por MAC.

## Comandos útiles

```
/system resource print
/system routerboard print
/interface print
/interface bridge port print
/interface bridge vlan print
/ip settings print
/ipv6 settings print
/ip address print
/export                      # en RouterOS 7 oculta los datos sensibles por defecto
/system reset-configuration no-defaults=yes
```

**Syslog.** La acción de fábrica `remote` (la número 3) envía a `10.20.20.10:514` por UDP con `bsd-syslog=yes`. Con `bsd-syslog=yes` el mensaje trae la hora y el nombre `sw01` en formato RFC 3164; con `no` (de fábrica) no trae el nombre. RouterOS 7.13 acepta una IPv6 en `remote` y envía desde `fd5a:fc7e:d716:10::2`. Las reglas `info`, `warning`, `error` y `critical` con `action=remote` se suman a las de memoria. Los logins (`user admin logged in from ... via ssh`) y los cambios de configuración (`... added by ssh:admin@...`) van con `info`.

**Safe Mode sin terminal interactiva.** Se puede usar por `ssh -tt` enviando Ctrl+X (`\x18`) como texto, los comandos con `\r` y otro Ctrl+X para confirmar. El usuario tiene que ser `admin+ct` (sin colores ni detección de terminal); con `admin` la detección se traga la entrada y no se aplica nada.

**Prueba de un puerto TCP desde la Interna.** RouterOS no tiene `nc`, pero `/tool fetch` sirve para comprobar si una conexión TCP pasa el firewall de kit01, en las dos familias. Si el estado llega a `requesting` la conexión se abrió, aunque después falle porque el servicio no habla HTTP. Si se queda en `connecting` el paquete se descartó.

```
/tool fetch url="http://10.20.20.11:445/" keep-result=no
/tool fetch url="http://[fd5a:fc7e:d716:20::11]:445/" keep-result=no
```

**HTTPS hacia clinica01.** `/tool fetch` por HTTPS no completa el handshake con el Caddy de clinica01 (`ssl: decode error`, ver `problemas-conocidos.md`); hacia comunidad01 sí. Para el 443 se usa la misma prueba por HTTP, `/tool fetch url="http://10.20.20.11:443/" keep-result=no`, que termina en `status 400` cuando Caddy contesta.

**Chips de switch y filtros.** Los dos chips son Marvell 88E6191X (`/interface ethernet switch print`). No aceptan reglas de switch (`/interface ethernet switch rule add` falla), y con la conmutación por hardware (`H` en `/interface bridge port print`) el filtro del bridge no ve el tráfico multicast que el chip reparte solo. Para filtrar en un puerto hay que ponerlo con `hw=no`. Con DHCP snooping activo, ether1 conserva la conmutación por hardware.
